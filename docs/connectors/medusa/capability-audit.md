# Capability audit

Only capabilities demonstrated by the current official interface and Connector SDK v1 are admitted. `products.write` supports update only: create is declared in the manifest for interface completeness but returns a normalized `unsupported` remote error, since Medusa's REST API has no reliable catalog-wide SKU lookup to guarantee idempotent creation. `notifications.receive` is declared but likewise returns `unsupported`: Medusa has no standardized outbound webhook delivery/signature contract this connector could verify against (Medusa's own docs describe reacting to events via in-process subscribers, not signed HTTP callbacks). `orders.status.write` supports only canceling an order (`POST /admin/orders/{id}/cancel`), the one unambiguous single-call lifecycle transition Medusa's REST API exposes directly on the order; every other transition (fulfillment, payment capture, ...) is a distinct sub-resource this SDK's single `StatusRemoteID` write contract cannot carry. No browser-cookie automation, private editor endpoints, raw card credentials, or provider-specific Core branches are permitted.

Official documentation: https://docs.medusajs.com/api/admin
