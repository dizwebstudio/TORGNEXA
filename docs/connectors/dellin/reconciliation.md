# Reconciliation

После admission runtime создаёт только ограниченные address-to-address заявки
и принимает асинхронные заявки на отмену address-delivery и pickup-from-address.
Статус
`cancellation_pending` не является финальной отменой: история «Деловых Линий»
остаётся удалённым источником истины и должна подтвердить или отклонить
изменение. Для Pre-Alert batch cancellation API возвращает завершённый
`data.state=success`, поэтому host сохраняет только нормализованное
`CANCELLED`-подтверждение; содержимое пакетной заявки не копируется. Неоднозначные
ответы попадают в reconciliation, а не повторяются вслепую; отмена отдельного
терминального заказа и возвраты не выполняются.
