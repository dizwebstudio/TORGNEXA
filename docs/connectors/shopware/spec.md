# Shopware 6 Connector Spec

Family: `storefront`. Self-hosted (host-injected, admin-supplied like WooCommerce/Medusa/OpenCart/PrestaShop), machine-to-machine OAuth2 client_credentials against a per-merchant Admin API, Shopware's Criteria search API.

Production networking is host-injected through a typed transport; provider code has no direct Core or SQL authority. Authentication uses Shopware's own "Integration" client id/secret (Settings > System > Integrations), exchanged for a short-lived bearer token by this connector itself (`POST /api/oauth/token`), the same self-contained pattern already established by `connectors/gigachat` — not the host-owned browser OAuth runtime used for Shopify, since Shopware's token endpoint is per-merchant and the grant is client_credentials, not authorization_code. The token (and the resolved currency entity id, since Shopware prices are keyed by currency UUID, not ISO code) are cached in-memory per call; because a fresh `ConfigurationSource` closure is bound on every registry call (self-hosted host varies per account, unlike gigachat's fixed host), this connector is constructed fresh per call like every other storefront connector, so the cache only pays off within one call's own sub-requests, not across separate top-level operations — an accepted efficiency trade-off, not a correctness issue.

Product variants use Shopware's parent/child product model (a `childCount > 0` parent has separate `product` rows with `parentId` set), not a nested variant array. Order status comes from the associated `stateMachineState.technicalName`. Money fields are parsed via `encoding/json.Number` to avoid float rounding.

Official documentation: https://developer.shopware.com/docs/guides/integrations-api/ ; entity/field shapes verified against the published Shopware core source at github.com/shopware/shopware (`src/Core/Content/Product`, `src/Core/Checkout/Order`).
