# План conformance для ПЭК

`connectors/logistics/pek` содержит sandbox-кандидат и детерминированные тесты без сети,
боевых ключей, адресов получателей и персональных данных.

Проверяются:

1. валидация и нормализация тарифов;
2. bounded создание одной заявки самовывозом, аннулирование, возврат одного
   принятого груза и чтение статуса отправления;
3. чтение отделений/ПВЗ;
4. чтение одной PDF-этикетки (`type=simple`) и печатной формы заявки
   (`type=big`) с проверкой сигнатуры и content digest;
5. callback-scoped доступ к секрету;
6. tenant isolation, rate-limit и idempotency probes общего harness.

Create в runtime ограничен одной заявкой типа `orderType=0` и не более 50 местами;
tenant-конфигурация sender warehouse обязательна. Адресная доставка,
сформированные грузы и пакетная печать (`type=multiple`) остаются отдельными
qualification-границами. Возврат одного принятого груза ограничен одним
числовым кодом через `/cargos/cancelandreturncargo/`; для live qualification
нужны тестовый аккаунт ПЭК, текущая версия API и обезличенные fixtures для
успеха, `success=false`, сетевой неопределённости и повторной сверки.
Аннулирование в runtime уже ограничено одной заявкой и точным подтверждением
кода в ответе.
