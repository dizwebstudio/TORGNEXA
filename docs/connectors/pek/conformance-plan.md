# План conformance для ПЭК

`connectors/logistics/pek` содержит sandbox-кандидат и детерминированные тесты без сети,
боевых ключей, адресов получателей и персональных данных.

Проверяются:

1. валидация и нормализация тарифов;
2. bounded создание одной заявки самовывозом, аннулирование и чтение статуса отправления;
3. чтение отделений/ПВЗ;
4. чтение одной PDF-этикетки (`type=simple`) и печатной формы заявки
   (`type=big`) с проверкой сигнатуры и content digest;
5. callback-scoped доступ к секрету;
6. tenant isolation, rate-limit и idempotency probes общего harness.

Create в runtime ограничен одной заявкой типа `orderType=0` и не более 50 местами;
tenant-конфигурация sender warehouse обязательна. Перед расширением create на
адресную доставку, сформированные грузы, возвраты или пакетную печать (`type=multiple`)
необходимо получить тестовый аккаунт ПЭК, зафиксировать текущую версию API,
добавить записанные
(обезличенные) fixtures и пройти повторяемость create/cancel/status на одном
idempotency key. Аннулирование в runtime уже ограничено одной заявкой и
точным подтверждением кода в ответе.
