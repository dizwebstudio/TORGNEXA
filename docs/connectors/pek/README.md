# ПЭК

ПЭК подключён к каталогу TORGNEXA в отдельном контуре «Доставка». В нём уже
доступны создание кабинета, шифрованное сохранение пары логин/ключ API и
проверка доступа к официальному API личного кабинета. Товарная синхронизация
через ПЭК не заявляется.

SDK-адаптер изолирует секреты callback-областью и нормализует расчёт тарифов,
bounded подачу одной заявки самовывозом, аннулирование предварительного
оформления, получение статуса и
справочника отделений. Защищённые runtime-
маршруты выполняют bounded read-only `pickup.points.read` через официальный
`/branches/all/`, `logistics.rates.read` через `/calculator/calculateprice/` и
`logistics.track.read` через `/cargos/basicstatus/`. Для расчёта сначала
выбираются активные склады запрошенных городов; ответ ограничивается 100
вариантами и переводит стоимость в целые копейки. Трекинг отправляет не более
одного кода груза за запрос, ограничивает ответ 50 грузами и переводит русские
статусы в нейтральные коды. Отмена отправляет один код через
`/order/cancellation/` и требует подтверждения того же кода в ответе.
Одиночная PDF-этикетка запрашивается через `/order/print/` с типом `simple`,
проверяется по base64 и сигнатуре `%PDF-`, после чего наружу выходит только
непрозрачная ссылка по digest. Полная печатная форма заявки доступна тем же
маршрутом с типом `big` через явный формат `request_pdf`; она проходит ту же
проверку и возвращается как отдельная digest-ссылка. Warehouse IDs остаются
внешними ссылками и не становятся ID складов TORGNEXA.

Create ограничен одной заявкой типа `orderType=0` с sender warehouse из
tenant-конфигурации, российским receiver, сервисом `pek_type_3` и максимум 50
местами. Ответ с `documentId` и одним `cargoCode` проверяется строго; provider
acceptance остаётся асинхронным и не считается сверкой. Отмена сформированного
груза и пакетные печатные формы (`type=multiple`) остаются закрыты. Возврат
одного уже принятого груза отправителю доступен через
`POST /api/v1/cargos/cancelandreturncargo/`: адаптер отправляет ровно один
`code`, принимает только `success=true` и нормализует подтверждённую операцию
как `logistics.return.create` с исходным кодом груза. Отрицательный ответ ПЭК
считается подтверждённым отказом, а сетевой timeout сохраняет неизвестный
результат в worker для сверки.

Источники протокола: [официальное описание API ПЭК](https://test-kabinet.pecom.ru/preweb/api/v1)
и [публичный API-калькулятор](https://pecom.ru/business/developers/api_public/).
