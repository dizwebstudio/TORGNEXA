# Сверка ПЭК

Статус груза ПЭК является удалённо-авторитетным наблюдением. После допуска
host-side logistics bridge должен сохранять только внутренний идентификатор
кабинета, канонический remote ID и нормализованный статус с временем
наблюдения. Сырые ответы API и данные получателей не сохраняются.

На текущем этапе приложение выполняет проверку доступа, bounded чтение статуса
груза из карточки «Доставка» и принимает запрос возврата одного принятого
груза через durable worker. Успешный ответ ПЭК сохраняется как созданный
возврат с исходным remote ID; `success=false` является подтверждённым отказом.
Сетевой timeout не повторяется автоматически и оставляет операцию в состоянии
неизвестного результата для сверки. Планировщик сверки ПЭК пока не включён;
live qualification должна использовать тестовый груз и проверять повторный
вызов после queued-ответа провайдера.
