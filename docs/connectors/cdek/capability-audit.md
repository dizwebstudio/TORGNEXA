# Capability audit

Only capabilities demonstrated by the current official interface and Connector SDK v1 are admitted. CDEK OAuth client credentials are checked against the token endpoint and a bounded city-directory read; the access token is discarded after the probe. The host transport and application runtime expose bounded read-only delivery-point, rate-preview and tracking routes when `pickup.points.read`, `logistics.rates.read` or `logistics.track.read` is explicitly enabled. Rate requests accept up to 50 parcels and normalize at most 100 tariff results using fixed-decimal money parsing. Tracking accepts one remote reference and normalizes at most 100 status records, selecting the latest valid timestamp. The application returns neutral option identifiers and tracking fields; remote tariff/PVZ identifiers remain provider-local. Shipment cancellation is admitted only through the tenant-scoped durable host route: a matching approved request, account capability, operation receipt, optimistic version, audit and transactional outbox are required before the worker calls the adapter; the adapter resolves a shipment number to a UUID and performs one DELETE by UUID. Creation, labels and returns remain closed until current fixtures, canonical service mapping and non-production qualification are retained. A timeout or ambiguous DELETE outcome is not blindly retried and must be reconciled from tracking. No browser-cookie automation, private editor endpoints, raw card credentials, or provider-specific Core branches are permitted.

Official documentation: https://apidoc.cdek.ru/
