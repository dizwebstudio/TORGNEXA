## Результат

Общий QueryClient заменён отдельным клиентом для каждого контекста сессии.
Контекст включает subject, host-owned scope, нормализованные роли и capability
claims. Смена пользователя, workspace или прав удаляет прежний QueryClient и
перемонтирует всё дерево авторизованного UI. Это охватывает кеши заказов,
финансов и остальных экранов через общую границу, без изменений каждого ключа.

Logout очищает состояние до ожидания host adapter. Исчезновение, некорректность,
ошибка проверки и истечение сессии также закрывают старый контекст. Отдельный
таймер убирает UI по expiry даже при незавершённом refresh; устаревший таймер
повторно проверяет срок текущей сессии. Обычное продление токена внутри того же
scoped-контекста сохраняет кеш.

Все запросы generated SDK получают AbortSignal владельца. Поздний 200/401,
включая транспорт, завершившийся вопреки abort, не может наполнить новый кеш,
обновить/завершить сессию B или повторить команду A с токеном B. Номера операций
защищают контроллер и встроенный Keycloak adapter от поздних refresh/login
результатов. Параллельные initial lookups, включая start-cleanup-start в React
StrictMode, ожидают один silent sign-in, вместо преждевременного anonymous.

## Контракт, совместимость и безопасность

- [ADR-0186](../../adr/0186-frontend-session-cache-lifetime.md) и
  [Auth Adapter v1](../../contracts/frontend/auth-adapter-v1.md) фиксируют
  необязательное `cacheScope`: bounded metadata только в памяти, без
  сериализации в public session, DOM, query keys, URL или browser storage.
- Встроенный адаптер составляет scope из issuer и tenant/workspace/login
  claims; это partition hint, а не доказательство полномочий. Сервер по-прежнему
  самостоятельно проверяет токен, membership, tenant/workspace и RLS.
- Host adapter должен сообщать о смене контекста через subscription и включать
  в scope весь свой workspace/identity context. Без `cacheScope` замена токена
  консервативно сбрасывает кеш; возможны дополнительные запросы и прерывание
  текущего запроса при renewal. Добавление/удаление scope также сбрасывает кеш.
- Новых зависимостей, persisted fields, SQL migrations, API/event изменений
  в A01 нет. Токены не используются как React/query keys. Все фикстуры
  синтетические. Отмена запроса не откатывает уже принятый сервером write.

## Границы результата и применение

Браузерный тест запускает реальное приложение с синтетическими host auth/API
ответами. Это проверка связки React/Query/SDK/UI; два реальных Keycloak-аккаунта
и внешние сервисы в этом сценарии не использовались. Гонки самого встроенного
OIDC-адаптера отдельно проверены logic-тестами. Backend/БД в A01 не менялись;
ранее выполненные PostgreSQL webhook-тесты здесь повторно не запускались.

Production bundle собран локально; Docker deployment не пересобирался и не
перезапускался. Для применения нужно обновить frontend artifact и перезагрузить
уже открытые вкладки: старый JavaScript сам не получит новую границу кеша.
A02, A09 и A10 этим изменением не закрыты; Task 234 остаётся `in_progress`.

Отдельное наблюдение о существующем validation script: npm передаёт его
`--outDir` последней команде составного build script, поэтому текущий полный
gate пишет bundle в `frontend/dist` и выдаёт предупреждение об аргументе.
Сборка проходит; исправление изоляции build output остаётся follow-up и не
входит в A01.
