# Migration 000011 — Orders

Task 006 adds canonical tenant-scoped `orders` and immutable `order_items`.

- An Order starts `pending` at version 1 and follows only `pending → confirmed/cancelled → processing/cancelled → fulfilled/cancelled` transitions.
- Commercial facts (number, currency, line snapshots, money/tax totals and `placed_at`) are immutable after creation; only status/version/timestamp advance.
- OrderItem stores exact coefficient+scale quantity, SKU snapshot, money snapshots and explicit tax treatment. No float columns are used.
- A deferred totals trigger verifies that Order subtotal/discount/tax/grand values equal its immutable items at commit.
- Forced RLS and composite tenant foreign keys isolate both tables; application hard delete/truncate is blocked.
- `connector_entity_mappings` is additively broadened to `entity_type=order`; provider order IDs and provider status names remain outside Core.
- New code emits `commerce.orders.order_changed.v1` through Transactional Outbox. The pre-existing `commerce.orders.order_created.v1` schema is not modified.
