# Migration 000015 — PIM / MDM

Task 023 adds canonical tenant-scoped Brand, Category and Attribute masters plus Product master-data assignments, field-authority rules, explainable duplicate candidates and immutable merge-preview evidence.

The migration is expand-only. Existing Product/Offer/Order tables and published mapping v1/v2 contracts remain intact. `connector_entity_mappings` is broadened additively to canonical `brand`, `category`, and `attribute` identities; provider taxonomy IDs remain outside Core.

Key invariants:
- all PIM tables use organization/workspace ownership and forced RLS;
- Brand/Category/Attribute code and identity are immutable and lifecycle is forward-only;
- Category parent and Attribute value type/multiplicity are immutable in v1;
- typed Product attribute values preserve decimal exactness by requiring decimal JSON strings;
- duplicate scores require bounded explainable signals and review state is forward-only;
- merge previews are append-only and fingerprinted; creating a preview never applies a merge;
- Product↔Brand/Category/Attribute relationships are tenant-bound through composite foreign keys;
- hard delete/truncate is unavailable to normal application flows.

Binary rollback retains the additive tables and evidence. A future contract migration may retire superseded shapes only after compatibility preconditions pass.
