TORGNEXA

TORGNEXA — открытая платформа для управления торговыми процессами между маркетплейсами, складами, ERP и интернет-магазинами.

Если Ozon показывает один остаток, WMS — другой, склад перестал отвечать, а заказы продолжают приходить, простой передачи данных между API уже недостаточно.

TORGNEXA хранит состояние торговых процессов и помогает решать, что делать дальше: где резервировать товар, сколько оставить каждому каналу продаж, когда повторять запрос, когда исключать склад и когда запускать сверку.

Что умеет
управлять остатками и резервами;
распределять товар между каналами продаж;
координировать заказы между маркетплейсами, ERP и WMS;
обрабатывать повторные события и ошибки API;
выполнять повторные попытки без дублирования операций;
находить расхождения между системами;
восстанавливать состояние после сбоев;
подключать внешние системы через коннекторы.
Пример

Есть три склада с общим остатком 175 единиц.

Один склад с 120 единицами перестал отвечать.

Обычная интеграция может продолжить передавать старые остатки в Wildberries и Ozon.

TORGNEXA должна:

обнаружить проблему
        ↓
исключить склад из новых назначений
        ↓
пересчитать доступный остаток
        ↓
проверить уже созданные резервы
        ↓
перераспределить товар между каналами
        ↓
обновить маркетплейсы
        ↓
после восстановления склада сверить состояние

Быстрый запуск
git clone https://github.com/dizwebstudio/TORGNEXA.git
cd TORGNEXA
make community-up

Проверить состояние:

make community-status

Остановить:

make community-down
Основной принцип архитектуры

Ядро TORGNEXA не зависит от конкретных поставщиков.

Ozon, Wildberries, Яндекс Маркет, ERP, WMS и другие системы подключаются через коннекторы и общие контракты.

Внутри ядра используются общие сущности:

Заказ
Товар
Остаток
Резерв
Склад
Отгрузка
Канал продаж

а не отдельная бизнес-логика для каждого маркетплейса.
