# TORGNEXA — open-source платформа для маркетплейсов и интернет-магазинов

[English version](README.md)

TORGNEXA — платформа с открытым исходным кодом, которую можно развернуть на
своей инфраструктуре. Она предназначена для команд, которые продают товары
через маркетплейсы, интернет-магазины и другие каналы: помогает синхронизировать
каталог, цены, остатки и заказы, а также вести доставку, возвраты и сверку
расчётов.

Проект подходит бизнесу, который хочет управлять своими операциями в одном
месте, подключать разные каналы продаж и строить автоматизацию поверх открытого
API, не привязываясь к одному провайдеру.

## Что можно делать с TORGNEXA

- поддерживать единые данные о товарах, ценах и остатках в разных каналах;
- собирать заказы с маркетплейсов и интернет-магазинов в общем процессе;
- связывать заказы с доставкой, возвратами и расчётами;
- запускать плановую синхронизацию и находить расхождения между локальными и
  удалёнными данными;
- расширять платформу через SDK коннекторов, REST API, webhooks и плагины.

## Интеграции

В репозитории есть коннекторы для маркетплейсов, включая Wildberries, Ozon,
Яндекс Маркет, Мегамаркет, Магнит Маркет и AliExpress RU. Среди интеграций с
интернет-магазинами — Shopify, WooCommerce, Magento, OpenCart и Shopware.
Текущий охват маркетплейсов и точные возможности описаны в
[руководстве по коннекторам маркетплейсов](docs/connectors/marketplaces.md), а
исходный код и тесты находятся в каталоге [`connectors/`](connectors/).

Модель коннекторов также используется для ERP, социальных сетей, платежей и
логистики. Каждая интеграция явно описывает свои возможности, изолирует детали
внешнего API и проходит общий набор проверок. Поэтому в документации видно,
что конкретный провайдер действительно поддерживает, а не только то, что он
присутствует в списке.

## Что работает сейчас

Репозиторий уже пригоден для локальной разработки и работы над коннекторами.
В текущий рабочий срез входят:

- Community-стенд на Docker Compose с API, веб-интерфейсом, фоновыми
  обработчиками, планировщиком, MCP-сервисом, PostgreSQL, Kafka и Valkey;
- веб-интерфейс с панелью управления, каталогом интеграций, документацией и
  настройками, где запросы учитывают организацию и рабочее пространство;
- REST API на основе OpenAPI и сгенерированные SDK для Go, Python и TypeScript;
- манифесты коннекторов, проверки возможностей и детерминированные
  conformance-тесты;
- локальные Docker-проверки для OpenCart, WooCommerce и PrestaShop,
  включая каталог, остатки и отдельные операции с товарами и заказами;
- документированные поверхности интеграций с маркетплейсами и интернет-магазинами,
  включая Wildberries, Ozon, Яндекс Маркет, Shopify, WooCommerce и Shopware.

Важно различать статусы: у провайдера может быть только чтение или health-check,
а успешный SDK conformance-тест не означает проверку реального аккаунта продавца.
Перед production-интеграцией смотрите [краткое резюме
валидации](VALIDATION_REPORT.md) и [матрицу возможностей маркетплейсов](docs/connectors/marketplaces.md).

## Статус проекта

TORGNEXA находится в активной разработке. Community-развёртывание доступно для
локального знакомства и разработки. Перед использованием в production нужно
проверить именно те коннекторы, потоки данных и топологию развёртывания, которые
будут использоваться.

## Запуск локально

Понадобятся Docker с Compose v2 и локальная копия репозитория.

```bash
make community-init
make community-up
make community-status
```

Community-стенд поднимает локальные сервисы, необходимые для знакомства с
платформой. Для браузерного smoke-теста выполните:

```bash
make community-e2e
```

Конфигурация и ротация секретов описаны в [руководстве по переменным
окружения](docs/deployment/environment-variables.md). Инструкции по запуску
есть для [Community через Docker](docs/deployment/093-community-docker-deployment.md)
и [production-развёртывания по SSH](docs/deployment/production-ssh-deploy.md).

## Структура проекта

- `docs/` — продуктовая, архитектурная и эксплуатационная документация;
- `adr/` — решения, объясняющие важные архитектурные выборы;
- `contracts/` — контракты API, событий, webhooks, плагинов и JSON Schema;
- `connectors/` — интеграции с маркетплейсами, интернет-магазинами, ERP,
  социальными сетями, платежами и логистикой;
- `internal/` — код приложения, предметной области и платформы;
- `frontend/` — веб-приложение;
- `tasks/` — задачи реализации и планы работ.

## Архитектура в двух словах

TORGNEXA начинается как модульный монолит на Go. PostgreSQL хранит основные
операционные данные; события проходят через EventBus и Kafka; аналитика и
история хранятся отдельно; кэш не используется как бизнес-хранилище.

Специфика провайдеров находится в коннекторах. Ядро работает через интерфейсы
и заявленные возможности, а не через проверки названий провайдеров. Архитектура
описана в [`docs/01-architecture.md`](docs/01-architecture.md) и зафиксирована
в [`docs/54-architecture-freeze-v1.md`](docs/54-architecture-freeze-v1.md).

## Участие в разработке

Начните с [описания продукта](docs/00-product-scope.md),
[архитектуры](docs/01-architecture.md) и
[границ модулей](docs/03-module-boundaries.md). Для изменений коннектора
прочитайте его manifest, спецификацию провайдера и conformance-тесты.

Для обычного изменения кода выполните:

```bash
gofmt -w <changed-go-files>
go test ./...
go vet ./...
./scripts/check-contracts.sh
```

В [`VALIDATION_REPORT.md`](VALIDATION_REPORT.md) хранится краткое резюме
проверки репозитория. Подробные runtime- и release-материалы должны храниться
в CI artifacts или в `qualification/evidence/`.
